# תרגיל סדנה: הפיכת כפתור NEXT לכפתור "שיר קודם"

## המטרה

כרגע, לחיצה על הכפתור הפיזי המחובר ל-**GPIO45** (המסומן NEXT) מעבירה לשיר **הבא** ברשימה. במשימה הזו נשנה את ההתנהגות כך שאותו כפתור פיזי יעביר לשיר **הקודם** במקום.

לא נוגעים בחיווט או בחומרה — רק בקוד.

---

## רקע: איפה ההתנהגות הזו מוגדרת

שלושה קבצים מעורבים:

1. **`src/main.cpp`** — הקובץ הראשי שרץ כל הזמן בלולאה (`loop()`). הוא בודק אם הכפתור הפיזי נלחץ, ואם כן — קורא לפונקציה `jukeboxUI.nextSong()`.
2. **`src/JukeboxUI.h`** — קובץ ה-header, שם **מוצהר** (declared) אילו פונקציות קיימות במחלקה `JukeboxUI` — כולל הרשימה `void nextSong();`.
3. **`src/JukeboxUI.cpp`** — קובץ המימוש (implementation), שם באמת **כתוב** מה `nextSong()` עושה.

כדי שהכפתור יעביר לשיר קודם, נבצע 3 שינויים: נוסיף פונקציה חדשה `previousSong()` (הצהרה + מימוש), ואז נגרום ל-`main.cpp` לקרוא לה במקום ל-`nextSong()`.

---

## שלב 1 — הוספת הצהרה (declaration) ב-`src/JukeboxUI.h`

פתחו את `src/JukeboxUI.h`. מצאו את השורה (בערך שורה 15):

```cpp
void nextSong();
```

**הוסיפו מיד אחריה** שורה חדשה, כך שיהיה:

```cpp
void nextSong();
void previousSong();
```

---

## שלב 2 — הוספת המימוש (implementation) ב-`src/JukeboxUI.cpp`

פתחו את `src/JukeboxUI.cpp`. מצאו את הפונקציה (בערך שורה 507):

```cpp
void JukeboxUI::nextSong()
{
    if (songCount() > 0)
    {
        const int current = max(0, _songIndex);
        selectSong((current + 1) % songCount());
    }
}
```

**מיד אחריה** הוסיפו פונקציה חדשה, דומה כמעט לגמרי — רק **במקום `+ 1`** (קדימה) נשתמש ב-**`+ songCount() - 1`** (חזרה אחורה, עם "גלגול" לסוף הרשימה כשמגיעים להתחלה):

```cpp
void JukeboxUI::previousSong()
{
    if (songCount() > 0)
    {
        const int current = max(0, _songIndex);
        selectSong((current + songCount() - 1) % songCount());
    }
}
```

**למה `+ songCount() - 1` ולא סתם `- 1`?** כי ב-C++ אופרטור ה-`%` (שארית) לא מתנהג יפה עם מספרים שליליים. `(current - 1) % songCount()` יכול לצאת שלילי אם `current == 0`, מה שיגרום לקריסה של הגישה למערך. הטריק `+ songCount() - 1` מבטיח שהתוצאה תמיד חיובית, ועדיין נותן את אותה "תזוזה של שיר אחד אחורה, עם גלגול".

**טיפ:** זה בדיוק אותו החישוב שכבר קיים באותו קובץ, בפונקציה `handleTouch()`, בטיפול בכפתור "<<" (שיר קודם) שמופיע במסך ה-HOME על המסך המגע. אפשר לחפש בקובץ ולמצוא שורה כמעט זהה — זה סימן טוב שעשיתם את זה נכון.

## שלב 3 — שינוי `src/main.cpp` כדי לקרוא לפונקציה החדשה

פתחו את `src/main.cpp`. מצאו את הבלוק שמטפל בלחיצה על כפתור NEXT (בערך שורה 155–159):

```cpp
else if (pressed)
{
    Serial.println("[Button] NEXT pressed");
    jukeboxUI.nextSong();
}
```

שנו את השורה `jukeboxUI.nextSong();` ל:

```cpp
jukeboxUI.previousSong();
```

(אופציונלי: אפשר גם לשנות את טקסט ה-`Serial.println` כך שישקף את מה שבאמת קורה עכשיו — זה לא משפיע על ההתנהגות, רק על מה שמודפס ללוג).

---

## שלב 4 — קומפילציה, העלאה, ובדיקה

1. שמרו את כל שלושת הקבצים.
2. הריצו `pio run -e esp32s3` ובדקו שאין שגיאות קומפילציה.
3. אם הכול תקין: `pio run -e esp32s3 -t upload` כדי להעלות לבקר.
4. **בדיקה בפועל**: לחצו על כפתור NEXT הפיזי — הג'וקבוקס אמור לעבור ל**שיר הקודם** ברשימה, לא הבא.

---

## הערה חשובה

התרגיל הזה משנה **רק** את כפתור ה-NEXT (GPIO45). כפתור ה-PLAY/PAUSE (GPIO46) ממשיך לעבוד בדיוק כמו קודם — מפעיל/עוצר את השיר הנוכחי, בלי שינוי.

שימו לב גם: אם אתם משחקים בפינבול או בהוקי אוויר מלשונית ה-GAMES, שני הכפתורים האלה משמשים כרגע כפקדי משחק (פליפר / מחבט) ולא כ-NEXT/PLAY-PAUSE. השינוי שעשיתם משפיע רק על ההתנהגות **כשלא משחקים במשחק** — תוכלו לראות את זה בקובץ `main.cpp`, בתנאי `if (jukeboxUI.isPlayingGame())` שמסביב לקוד שהשתנה.

## אתגר בונוס (לא חובה)

למי שרוצה אתגר נוסף: אפשר לנסות לגרום לאותו כפתור פיזי להתנהג אחרת בהתאם לזמן הלחיצה — לחיצה קצרה = שיר הבא (ההתנהגות המקורית), לחיצה ארוכה (מוחזקת) = שיר קודם. (רמז: תצטרכו למדוד זמן לחיצה עם `millis()`, בדומה לאיך שכבר נעשה דיבאונס לכפתורים בקובץ `main.cpp`).
