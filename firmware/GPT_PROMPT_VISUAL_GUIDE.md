# תרגיל סדנה: הפיכת כפתור NEXT לכפתור "שיר קודם"

## המטרה
כרגע, לחיצה על הכפתור הפיזי המחובר ל-GPIO45 (המסומן NEXT) מעבירה לשיר הבא ברשימה. במשימה הזו נשנה את ההתנהגות כך שאותו כפתור פיזי יעביר לשיר הקודם במקום. לא נוגעים בחיווט או בחומרה — רק בקוד.

## רקע: איפה ההתנהגות הזו מוגדרת
שלושה קבצים מעורבים:
1. src/main.cpp — הקובץ הראשי שרץ כל הזמן בלולאה (loop()). הוא בודק אם הכפתור הפיזי נלחץ, ואם כן — קורא לפונקציה jukeboxUI.nextSong().
2. src/JukeboxUI.h — קובץ ה-header, שם מוצהר (declared) אילו פונקציות קיימות במחלקה JukeboxUI — כולל השורה void nextSong();.
3. src/JukeboxUI.cpp — קובץ המימוש (implementation), שם באמת כתוב מה nextSong() עושה.

כדי שהכפתור יעביר לשיר קודם, נבצע 3 שינויים: נוסיף פונקציה חדשה previousSong() (הצהרה + מימוש), ואז נגרום ל-main.cpp לקרוא לה במקום ל-nextSong().

## שלב 1 — הוספת הצהרה ב-src/JukeboxUI.h
פתחו את src/JukeboxUI.h. מצאו את השורה (בערך שורה 15):
```
void nextSong();
```
הוסיפו מיד אחריה שורה חדשה, כך שיהיה:
```
void nextSong();
void previousSong();
```

## שלב 2 — הוספת המימוש ב-src/JukeboxUI.cpp
פתחו את src/JukeboxUI.cpp. מצאו את הפונקציה (בערך שורה 507):
```
void JukeboxUI::nextSong()
{
    if (songCount() > 0)
    {
        const int current = max(0, _songIndex);
        selectSong((current + 1) % songCount());
    }
}
```
מיד אחריה הוסיפו פונקציה חדשה, דומה כמעט לגמרי — רק במקום + 1 (קדימה) נשתמש ב- + songCount() - 1 (חזרה אחורה, עם "גלגול" לסוף הרשימה כשמגיעים להתחלה):
```
void JukeboxUI::previousSong()
{
    if (songCount() > 0)
    {
        const int current = max(0, _songIndex);
        selectSong((current + songCount() - 1) % songCount());
    }
}
```
טיפ (הסבר "למה"): למה + songCount() - 1 ולא סתם - 1? כי ב-C++ אופרטור ה-% (שארית) לא מתנהג יפה עם מספרים שליליים. (current - 1) % songCount() יכול לצאת שלילי אם current == 0, מה שיגרום לקריסה של הגישה למערך. הטריק + songCount() - 1 מבטיח שהתוצאה תמיד חיובית, ועדיין נותן את אותה "תזוזה של שיר אחד אחורה, עם גלגול".

טיפ נוסף: זה בדיוק אותו החישוב שכבר קיים באותו קובץ, בפונקציה handleTouch(), בטיפול בכפתור "<<" (שיר קודם) שמופיע במסך ה-HOME על מסך המגע. אפשר לחפש בקובץ ולמצוא שורה כמעט זהה — זה סימן טוב שעשיתם את זה נכון.

## שלב 3 — שינוי src/main.cpp כדי לקרוא לפונקציה החדשה
פתחו את src/main.cpp. מצאו את הבלוק שמטפל בלחיצה על כפתור NEXT (בערך שורה 155–159):
```
else if (pressed)
{
    Serial.println("[Button] NEXT pressed");
    jukeboxUI.nextSong();
}
```
שנו את השורה jukeboxUI.nextSong(); ל:
```
jukeboxUI.previousSong();
```
(אופציונלי: אפשר גם לשנות את טקסט ה-Serial.println כך שישקף את מה שבאמת קורה עכשיו — זה לא משפיע על ההתנהגות, רק על מה שמודפס ללוג).

## שלב 4 — קומפילציה, העלאה, ובדיקה
1. שמרו את כל שלושת הקבצים.
2. הריצו pio run -e esp32s3 ובדקו שאין שגיאות קומפילציה.
3. אם הכול תקין: pio run -e esp32s3 -t upload כדי להעלות לבקר.
4. בדיקה בפועל: לחצו על כפתור NEXT הפיזי — הג'וקבוקס אמור לעבור לשיר הקודם ברשימה, לא הבא.

## הערה חשובה (תיבת אזהרה/הבהרה)
התרגיל הזה משנה רק את כפתור ה-NEXT (GPIO45). כפתור ה-PLAY/PAUSE (GPIO46) ממשיך לעבוד בדיוק כמו קודם. שימו לב גם: אם משחקים בפינבול או בהוקי אוויר מלשונית ה-GAMES, שני הכפתורים משמשים כרגע כפקדי משחק ולא כ-NEXT/PLAY-PAUSE — השינוי משפיע רק כשלא משחקים במשחק (ראו את התנאי if (jukeboxUI.isPlayingGame()) ב-main.cpp).

## אתגר בונוס (לא חובה)
למי שרוצה אתגר נוסף: לנסות לגרום לאותו כפתור פיזי להתנהג אחרת בהתאם לזמן הלחיצה — לחיצה קצרה = שיר הבא (המקורי), לחיצה ארוכה = שיר קודם. רמז: תצטרכו למדוד זמן לחיצה עם millis(), בדומה לדיבאונס הקיים לכפתורים ב-main.cpp.
